Why another CAT tool

Because the ones we use weren't built by people who translate all day.

Your memory stays yours

Translation memories live in an open, documented SQLite format. TMX goes in and out, and your old Trados memories import directly — no export dance, no lock-in.

Formatting you can trust

Every change runs against a roundtrip gate: if exporting an untouched document alters a single byte, the build fails. Tags are placed by kind and order, in the receiving document's formatting.

Every change has a name

Each edit is logged with the person who made it, in the same write, to a history nothing can rewrite — and a hash chain lets audit-verify prove it. An AI draft or a TM match is where the text came from, never who signed it off.

Basics first, then AI

Version one is a dependable replacement for the desktop tool you already use: import, segment, match, check, export. AI assistance, quoting and vendor work get built on top once that is solid — not instead of it.

Who we're looking for

You know what a broken tag costs at 11 p.m. before a deadline.

And you can write code. That combination is rare, and it's what this project needs most.

  • Translators, reviewers and PMs who program — TypeScript ideally, but a strong grasp of any language and a willingness to read a spec will do.
  • People who have fought OOXML, TMX, XLIFF or Trados packages and have opinions about them.
  • Native speakers of languages we don't segment yet — Korean and Vietnamese are waiting on rules right now.
  • Front-end developers who care about keyboards. The editor has to be faster than the one you're used to, or nobody will switch.

How to join

Three steps, no application form.

  1. Read the ground rules

    The README for the layout, then CLAUDE.md for how work happens here: spec before code, one issue per branch, and the invariants that are not up for debate.

  2. Introduce yourself

    Open an introduction: your language pairs, the CAT tools you use, what you can build. It takes five minutes.

  3. Pick a card

    Every open piece of work is a GitHub issue linked to its spec. Say which one you're taking, and we'll talk it through before you write code.
