# Glossary

The repo's own working vocabulary: each domain word fixed once. Read it before naming anything (code, docs, UI text, PR titles) and add a row in the same PR as a change that adds or redefines a term. This is not the client termbase, which lives in `.ctg` files.

Rows marked _unconfirmed_ are a first reading from the code and specs, not yet checked by Louis.

| Term              | Definition                                                                                                                                                                 | Avoid                                          | Source                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------- |
| actor             | The accountable human, or a named `system:` job, behind an audited write; required on every such write.                                                                    | user (for an AI engine or a TM match)          | `planning/audit-spec.md`                 |
| assignment        | One job offered to a vendor for one project of an owner, moving through offered or pool_open, claimed, accepted or declined, in progress, delivered and reviewed.          | task                                           | `planning/vendor-spec.md` §4             |
| audit event       | An append-only row recording a change that matters, written in the same transaction and file as the data it describes.                                                     | log line                                       | `planning/audit-spec.md`                 |
| background job    | Bulk work run on a worker thread and polled by an unguessable id (a memory import, a stale-work scan), never done inside a request. _unconfirmed_ (the UI also says "job") | job (alone, when it could mean an assignment)  | `packages/server/src/jobs.ts`            |
| backlog entry     | A record in `planning/v1-backlog.md` of what shipped and what it taught; its status is the GitHub issue's, never the file's.                                               | ticket                                         | `CLAUDE.md`                              |
| card              | A GitHub issue on the board, one per open backlog entry.                                                                                                                   | ticket, task                                   | `CLAUDE.md`                              |
| `.ctg`            | The smart glossary file: a `.ctm`-shaped SQLite file of terms, variants and an append-only decision log.                                                                   | glossary table in `portal.sqlite`              | `planning/smart-glossary-spec.md`        |
| `.ctm`            | The translation memory file: a SQLite file of translation units, written through the shared migration runner.                                                              | TM file (in user-facing text)                  | `planning/tm-format-spec.md`             |
| `.ctv`            | The vendor roster file: one per owner account, holding vendors, rates, capacity, assignments and payments.                                                                 | per-vendor file                                | `planning/vendor-spec.md` §5             |
| deadline notice   | One of two webhook events, a reminder before a job's deadline or an overdue report once it has passed, each sent once per assignment.                                      | late alert, SLA alert                          | `planning/vendor-spec.md`, the #155 note |
| direct offer      | An assignment channel that offers a job to one named vendor; a decline is never converted to a pool post by itself.                                                        | private offer                                  | `planning/vendor-spec.md` §4             |
| fuzzy match       | A TM match scored 0 to 99 by the FS-2 scorer; its origin is `tm_fuzzy_<score>`, never a band.                                                                              | partial match                                  | `planning/v1-spec.md` §6.1a              |
| golden test       | The end-to-end CLI test comparing one real job's whole transcript to `fixtures/golden/`; a diff is read, not regenerated.                                                  | snapshot test                                  | `CLAUDE.md`                              |
| hidden tag        | A format tag a translator never places (fonts, bookmarks, drawings), carried onto every stored target by `carryHiddenTags`.                                                | invisible tag                                  | `CLAUDE.md`                              |
| ICE match         | An exact match whose preceding and following segment hashes also match, so it is safe to accept unreviewed.                                                                | 101% match                                     | `planning/tm-format-spec.md` §5          |
| match tier        | The category a segment's words are counted and paid under: no match, a fuzzy band, exact or ICE.                                                                           | match type                                     | `planning/v1-spec.md` §6.1a              |
| memory            | The UI and API name for a translation memory (`.ctm`), addressed by slug, never by path.                                                                                   | TM (in user-facing text)                       | `CLAUDE.md`                              |
| origin            | Where a segment's target came from (a TM match, a fuzzy score, an AI engine); never an actor.                                                                              | source (of a draft)                            | `planning/audit-spec.md`                 |
| override          | A glossary decision that is a ruling: it moves a term's preferred rendering at once.                                                                                       | exception                                      | `CLAUDE.md`                              |
| owner             | An account with the owner role, which owns projects, memories, glossaries and one roster.                                                                                  | client, admin                                  | `planning/v1-spec.md` §4.1a              |
| payable           | The amount owed a vendor for a delivered assignment, locked at delivery from the frozen tier words and the rates of the offer's date.                                      | invoice                                        | `planning/vendor-spec.md`                |
| pool              | An assignment channel posting a job to a set of eligible vendors, first claim wins.                                                                                        | open offer                                     | `planning/vendor-spec.md` §4             |
| portal            | The client-facing intake and delivery surface, a separate product surface from the CAT engine.                                                                             | client app                                     | `planning/portal-v0-spec.md`             |
| reminder lead     | The number of hours before a deadline at which an owner's reminder goes, 24 unless set, 0 for none.                                                                        | reminder window, notice period                 | `planning/vendor-spec.md`, the #155 note |
| roster            | An owner's `.ctv`: the vendors they engage, with languages, specialties, rates and capacity.                                                                               | vendor list                                    | `planning/vendor-spec.md` §5             |
| roundtrip gate    | The test that a zero-edit DOCX import and export reproduces every part byte for byte across the fixture corpus.                                                            | roundtrip test                                 | `CLAUDE.md`                              |
| segment exception | Evidence that a glossary rendering was deliberately not used in one segment; never a ruling, and only enough of them propose an override.                                  | override                                       | `CLAUDE.md`                              |
| skeleton          | A DOCX part's original XML kept as a string sliced around its segments, never a re-serialised tree.                                                                        | template                                       | `CLAUDE.md`                              |
| stale use         | A memory unit whose target uses a rendering the glossary now forbids, or a non-preferred one that is present.                                                              | outdated translation                           | `planning/smart-glossary-spec.md` §6.2   |
| term              | A glossary entry: one concept with its variants per language, one of them preferred.                                                                                       | word, entry (alone)                            | `planning/smart-glossary-spec.md`        |
| vendor            | An account with the vendor role on an owner's roster, who receives and delivers assignments.                                                                               | translator (when the role matters), freelancer | `planning/vendor-spec.md`                |
| vendor record     | Two counts over a vendor's assignments, offers accepted of those answered and deliveries on time of those with a deadline; advisory, never a score.                        | scorecard, rating                              | `planning/vendor-spec.md`, the #123 note |
| webhook delivery  | One queued signed POST of an assignment or payable event to an owner's endpoint, written in the same transaction as the event and retried on a schedule.                   | notification, callback                         | `planning/vendor-spec.md`, the #125 note |
| webhook endpoint  | An HTTPS address an owner registered, with the secret that signs what is sent to it.                                                                                       | subscription, hook URL                         | `planning/vendor-spec.md`, the #125 note |
| write target      | The one memory or glossary a project writes new entries to.                                                                                                                | default memory                                 | `CLAUDE.md`                              |
